1. Executive Summary
Product Analyzer is an AI-powered web app that lets Indian entrepreneurs research any product market in under 3 minutes — completely free to build and run. A user types a product name and receives a full market intelligence report: pricing across Indian e-commerce platforms, demand trends, top competitors, import viability from China, and Indian legal/regulatory requirements.

Version 2.0 of this PRD replaces all paid APIs with carefully selected free-tier services that together cost ₹0 to operate at prototype and early-user scale. The AI brain is Google Gemini 2.5 Flash (free, 250 requests/day), search data comes from Serper.dev (2,500 free queries on signup), trends from pytrends (Google Trends, completely free), and the app is hosted on Vercel + Render (both free). The entire stack can be set up in a weekend.

2.1 Why Gemini 2.5 Flash (not Gemini Pro)?
Flash gives 250 free requests/day vs 100 for Pro — 2.5x more capacity
Flash is fast enough for structured JSON report generation (our use case)
1 million token context window — enough to pass all scraped data in one call
No credit card required to get the API key from Google AI Studio
Strategy: use Flash for all reports; reserve Pro API calls only for complex legal lookups

3. Problem Statement
3.1 The Problem
Manual product research across Amazon, Flipkart, Alibaba etc. takes 8–15 hours per product
No free tool in India combines pricing + demand + competition + legal compliance in one place
Indian importers make ₹2–10 lakh import decisions based on gut instinct, not data
Legal requirements (BIS certification, FSSAI, customs duty, GST) are confusing and scattered across 5+ government portals
First-time sellers lose money because they don't know the landed cost or required licenses upfront

3.2 Target Users
First-time importers evaluating whether to import a product from China
Amazon/Flipkart/Meesho sellers looking for new product categories to add
D2C founders researching white-label product opportunities
Procurement agents and sourcing consultants
Students and entrepreneurs validating business ideas before investing

5. System Architecture (Zero-Cost)
5.1 Data Flow
User submits product name via React frontend
Vercel Edge Function OR Render FastAPI receives request
Check Upstash Redis cache — if same product searched in last 24h, return cached report
If cache miss: run 3 parallel tasks —
Task A: Serper.dev — 5 queries (Amazon IN prices, Flipkart prices, Google Shopping, market overview, top brands)
Task B: pytrends — fetch 12-month Google Trends interest data for the product
Task C: Supabase legal DB lookup — match product to BIS/HSN/GST/DGFT data
All raw data bundled into one large prompt → sent to Gemini 2.5 Flash API
Gemini returns structured JSON report (~800–1200 tokens)
Report stored in Supabase; returned to frontend
Frontend renders interactive report with charts, score rings, SWOT grid

6. Step-by-Step Build Guide
Step 1 — Set Up Free API Keys (Day 1, ~1 hour)
Gemini API: Go to aistudio.google.com → Create API key → copy to .env as GEMINI_API_KEY
Serper: Go to serper.dev → Sign up → Get API key (2,500 free queries credited instantly)
Supabase: Go to supabase.com → New project → copy SUPABASE_URL and SUPABASE_ANON_KEY
Upstash: Go to upstash.com → Create Redis DB → copy UPSTASH_URL and UPSTASH_TOKEN

Step 2 — Backend Setup (Day 1–2)
pip install fastapi uvicorn google-generativeai pytrends requests beautifulsoup4 upstash-redis supabase
Create main.py with FastAPI app and /api/analyze POST endpoint
Write parallel_fetch() using asyncio.gather() for Serper + pytrends + legal DB
Write gemini_report() that takes raw data dict and returns structured JSON
Add Redis caching: check cache before fetching, store result for 24 hours
Deploy to Render: connect GitHub repo, set env vars, auto-deploy on push

Step 3 — Gemini Prompt Engineering (Critical)
Your Gemini prompt must be precise. Key rules for getting good structured output:
Always tell Gemini: 'Respond ONLY with valid JSON, no markdown, no backticks'
Pass all raw search data in the prompt — Gemini's 1M token context handles it easily
Ask for specific JSON schema with exact field names — validate with Pydantic on the backend
Use temperature=0.2 for consistent structured outputs (lower = more deterministic)
Include Indian market context: 'This is for the Indian market. All prices in INR.'

Step 4 — Legal Database Setup (Day 2–3)
The legal data is a static lookup table — not scraped. Build it once, maintain quarterly.
Create a Supabase table: product_legal with columns: category, keywords[], bis_required (bool), bis_standard, hsn_code, customs_duty_pct, gst_pct, fssai_required (bool), dgft_status, legal_metrology (bool), notes
Populate 100 most common import categories manually (electronics, toys, apparel, cosmetics, food, appliances, sports goods, etc.)
Sources: bis.gov.in mandatory product list + cbic.gov.in tariff schedule + dgft.gov.in trade policy
On backend: use keyword matching to map user's product to nearest legal category
Gemini does the final interpretation: 'Based on this legal data, what applies to THIS product?'

Step 5 — Frontend Setup (Day 3–4)
npm create vite@latest product-analyzer -- --template react
npm install tailwindcss recharts axios supabase jspdf
Build 6 tab components: Overview, Pricing, Demand, Competition, Legal, Verdict
Add margin calculator with useState slider (no backend call needed)
Render Recharts LineChart for pytrends data
Add loading states with progress bar (fake steps every 10 seconds)
Deploy to Vercel: vercel --prod (auto-detects Vite, deploys in 30 seconds)

7. Free Data Collection Strategy
7.1 Serper.dev — Primary Search Source
Each product analysis triggers these 5 Serper queries (= 5 credits per report):
Query 1: '[product] price site:amazon.in' — gets Amazon India pricing
Query 2: '[product] price site:flipkart.com' — gets Flipkart pricing
Query 3: '[product] buy India price' — Google Shopping results with multiple sellers
Query 4: 'best [product] brands India review' — top brands and competition
Query 5: '[product] import india market size 2024 2025' — market overview
This uses 5 of your 2,500 free credits per report = 500 full reports before needing to upgrade.

7.2 pytrends — Google Trends (Completely Free)
Use the pytrends Python library. No API key required — it directly queries Google Trends.
Fetch interest_over_time() for past 12 months for the product name
Fetch related_queries() for discovering sub-variants and related search terms
Add time.sleep(2) between calls to avoid rate limiting
Cache results in Redis — Trends data is stable for 24 hours

7.3 BeautifulSoup Scraping — Fallback
When Serper credits run low, fall back to direct scraping for basic price data:
Amazon India search page: extract product titles + prices from HTML
Add random User-Agent headers and 2–5 second delays to avoid blocks
This is a fallback only — Serper results are more reliable and structured
Note: Flipkart is harder to scrape due to anti-bot measures — rely on Serper for Flipkart

8. Indian Legal & Regulatory Framework
8.1 Regulatory Bodies Covered
BIS (Bureau of Indian Standards) — mandatory product certifications for electronics, toys, helmets, appliances, cables, switches, etc.
FSSAI — for all food products, health supplements, packaged water, nutraceuticals
Legal Metrology — mandatory for ALL packaged commodities sold in India: MRP, date, importer name, country of origin, net quantity
CDSCO — medical devices and cosmetics
DGFT — import licensing: freely importable vs. restricted vs. canalised
CBIC — customs duty classification using HSN codes
MoEFCC — e-waste EPR for electronics; plastic EPR for plastic-heavy products

10. Risks & Free-Tier Mitigations

HIGH
Fallback to Tavily (1,000 free/month recurring) + BS4 scraping for price-only queries. Serper credits last 500 reports.

MEDIUM

Amazon blocks scraper
